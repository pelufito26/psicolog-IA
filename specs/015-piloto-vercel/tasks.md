# Tareas del piloto en Vercel

VERCEL-tasks-r1 · Aprobadas junto con VERCEL-plan-r1 mediante «sip aprobueo».

- [ ] T1 — Base y destino (V1, V6, V8): verificar main con PR16, conservar cambios ajenos, rama, scope personal y proyecto nuevo psicologia-piloto. Registrar alias/ID reales y compatibilidad del plan sin contratar; inventariar variables y presupuesto de conexiones/correo. Hecho cuando el destino es inequívoco y la secuencia puede ejecutarse sin afectar proyectos de v0.
- [ ] T2 — Entorno y API portable (V1–V4, V6): construcción de app separada del listener local, entrada Node en api/, configuración/routing Vercel, origen explícito y cookies seguras, restricción de cuenta piloto y secretos estables por propósito. Hecho cuando se conserva local, el piloto falla cerrado ante configuración inválida y dos instancias aceptan las versiones válidas sin admitir tokens ajenos. Depende de T1.
- [ ] T3 — Persistencia y pruebas (V4–V7): CA por variable, TLS verificado, pooler con rol restringido, presupuesto conjunto de conexiones y contexto transaccional. Regresiones de configuración/rutas/seguridad/instancias, check, PostgreSQL desechable con dos profesionales y empaquetado Vercel sin secretos. Hecho cuando hay evidencia reproducible, sin pruebas destructivas remotas ni ampliación de privilegios. Depende de T2.
- [ ] T4 — Revisión y publicación del cambio (V6, V8): documentación de despliegue y matriz V1–V8, revisión independiente, resolver hallazgos, diff/archivos explícitos, commit y PR con CI verde del SHA a desplegar. Hecho cuando el cambio funcional revisado está trazado y no se ha mergeado por el agente. Depende de T3.
- [ ] T5 — Configuración y despliegue del piloto (V1–V6): variables solo Production del proyecto nuevo, alias exacto en Supabase y Site URL, SMTP sin cambios, despliegue manual del commit revisado. Hecho cuando la URL sirve frontend/API, HTTPS/orígenes/cookies son correctos y anónimos/identidades no autorizadas quedan bloqueados. No iniciar pruebas clínicas antes de estas comprobaciones. Depende de T4.
- [ ] T6 — Aceptación online y cierre (V3, V5, V7–V8): ingreso personal del usuario, recorrido CU01–CU11 ficticio, persistencia, escritorio/móvil/otro dispositivo y logout. Documentar verificado/no ejecutado, CI/SHA/URL y reversión/retirada sin borrar datos. Hecho cuando se aporta evidencia del piloto o se declara con precisión el pendiente que impide aceptarlo; nunca marcar completo por un build verde. Depende de T5.

Aprobar VERCEL-plan-r1 y VERCEL-tasks-r1 autoriza el lote descrito sin consultas rutinarias adicionales. Las intervenciones personales para autenticación y transferencia sensible de credenciales se coordinan cuando sean necesarias. Si una dependencia exige pago, permisos nuevos, otro destino o mayor alcance de correo/datos, detener únicamente ese efecto y presentar la necesidad concreta.
